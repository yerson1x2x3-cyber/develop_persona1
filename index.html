Scrum Framework

Marco de trabajo ágil basado en entregas iterativas e incrementales.

  • Roles: Product Owner, Scrum Master, Developers.
  • Eventos: Sprint Planning, Daily Scrum, Sprint Review, Retrospective.
  • Artefactos: Product Backlog, Sprint Backlog, Incremento.
Metodología Kanban

Sistema visual para gestionar el trabajo a medida que avanza a través de un proceso.

  • Visualización clara del flujo de trabajo (To Do, In Progress, Done).
  • Limitación del Trabajo en Proceso (WIP).
  • Mejora continua y gestión ágil del tiempo.
Extreme Programming (XP)

Enfoque centrado en la calidad del código y la excelencia técnica.

  • Programación en pareja (Pair Programming).
  • Pruebas continuas (QA vs Testing).
  • Integración Continua y Refactorización.
El Manifiesto Ágil - Mejorado US-01

4 Valores fundamentales:

  1. Individuos e interacciones sobre procesos y herramientas.
  2. Software funcionando sobre documentación extensiva.
  3. Colaboración con el cliente sobre negociación contractual.
  4. Respuesta ante el cambio sobre seguir un plan.

12 Principios Ágiles (Resumen):

  • Satisfacción del cliente mediante entregas tempranas y continuas.
  • Bienvenida a cambios, incluso tardíos.
  • Entregas frecuentes de software funcional.
  • Trabajo conjunto entre negocio y desarrolladores.
  • Motivación y confianza en el equipo.
  • Comunicación cara a cara.
  • Software funcionando como medida de progreso.
  • Desarrollo sostenible y ritmo constante.
  • Atención continua a la excelencia técnica.
  • Simplicidad: maximizar trabajo no hecho.
  • Equipos auto-organizados generan mejores diseños.
  • Reflexión y ajustes regulares para mejorar efectividad.

Laboratorio Práctico: Gestión Ágil en GitHub

Objetivo: Configurar un repositorio en GitHub para simular el flujo de trabajo de Scrum y Kanban.

  1. Ingresar a GitHub.com e iniciar sesión.
  2. Crear un nuevo repositorio público llamado agile-scrum-lab.
  3. Ir a la pestaña Projects y seleccionar New Project -> Plantilla Board (Kanban).

  • Crear un Milestone llamado Sprint 1 - MVP.
  • Registrar las Historias de Usuario como Issues.
  • Vincular cada Issue al Milestone y asignarla.
